# Общажный ЧР

React Native + Expo Router для Android с Expo Go. Frontend подключён к [FastAPI + PostgreSQL](backend/README.md): регистрация, вход, профиль, справочники, поиск, объявления, фотографии, статусы и чаты используют сервер. Демо-пользователи и локальные объявления из приложения удалены.

## Запуск

Сначала запустить бэкенд по [инструкции](backend/README.md), применить миграции и заполнить справочник вузов. Для телефона API должен слушать LAN-интерфейс компьютера:

```powershell
# Из backend, с настроенным .env:
.\.venv\Scripts\python.exe -m uvicorn src.main:create_app --factory --host 0.0.0.0 --port 8000

# Во втором терминале, из D:\Projects\Mobilki:
npm.cmd install
npm.cmd start
```

Открыть Expo Go и отсканировать QR-код. Телефон и компьютер должны быть в одной Wi-Fi-сети; порт API 8000 должен быть доступен телефону. Используется Expo SDK 57. В браузере — `npm.cmd run web`, затем http://localhost:8081. Новый аккаунт создаётся через «Нет аккаунта? Создать»; почта/пароль проверяются сервером, минимальная длина пароля — 8 символов.

## Адрес API

По умолчанию браузер использует свой hostname с портом 8000, Expo Go — hostname из конфигурации Metro с тем же портом. Localhost в URL фотографий преобразуется в адрес доступного клиенту API, поэтому картинки загружаются и с телефона.

Для собственного сервера создать `.env` в корне проекта:

```dotenv
EXPO_PUBLIC_API_URL=https://api.example.com/api/v1
```

В адресе нужен суффикс `/api/v1`. Это публичная настройка, секретов в ней нет. После изменения полностью перезагрузить приложение. При `expo start --tunnel` адрес API тоже нужно задать явно: туннель Expo передаёт только приложение, не бэкенд.

Если VPN заставляет Expo выбирать не тот интерфейс, указать IP Wi-Fi в текущем терминале:

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME='IP_ВАШЕГО_КОМПЬЮТЕРА'
npm.cmd start
```

В этой сессии использован Wi-Fi IP `10.182.26.90`, API на 8000, Metro на 8081. Это адрес локальной сети, который может измениться. При использовании веб-версии с другого origin добавить его в CORS_ORIGINS бэкенда. Для рабочего домена используется HTTPS.

## Поведение

- Токен сохраняется на Android в нативном SecureStore, в web-preview — в AsyncStorage/localStorage. На устройстве сохраняется только токен, пароль и серверные списки не сохраняются.
- После запуска токен проверяется через `/users/me`. Ошибка сети предлагает повтор; `401` удаляет токен и открывает вход. Выход очищает токен и приватное состояние.
- Вузы/общежития приходят с сервера. Можно выбрать существующее общежитие или ввести новое название/номер при регистрации и редактировании профиля.
- Поиск и фильтры выполняет сервер; лента имеет кнопку следующей страницы. Все списки используют `offset` и `size`, ответ — `{items}` без курсоров. Фронтенд увеличивает смещение на число полученных записей; неполная или пустая страница завершает загрузку. Профиль показывает только собственные объявления по серверному ID автора.
- Объявления не содержат отдельных полей условий обмена и места встречи. Эти сведения обсуждаются в описании/переписке. Формат «Обмен» сохранён.
- Фото передаются multipart-файлами. При ошибке после сохранения объявления форма запоминает его серверный ID, поэтому повтор загрузки не создаёт ещё одно объявление.
- Чаты обновляются по HTTP каждые 3–4 секунды, пока соответствующий экран открыт. В фоне прочтение не отмечается. История загружается страницами; повтор отправки сообщения использует тот же UUID.
- Скелетоны соответствуют реальной загрузке. Ошибки показываются в интерфейсе; неуспешный запрос не считается успешным локальным изменением.

Нативные адаптеры в `src/shared/api/runtime.ts` и `src/shared/lib/message-id.ts` используют встроенные в Expo Go SDK 57 модули ExpoSecureStore и ExpoCrypto. Два npm-пакета не удалось скачать из-за недоступного registry; дополнительных зависимостей не добавлено. Сигнатуры сверены с [SecureStore SDK 57](https://github.com/expo/expo/blob/sdk-57/packages/expo-secure-store/src/SecureStore.ts) и [Crypto SDK 57](https://github.com/expo/expo/blob/sdk-57/packages/expo-crypto/src/Crypto.ts). Для отдельной native-сборки потребуется установить совместимые expo-secure-store/expo-crypto и настроить их autolinking/plugin: адаптер рассчитан на согласованный запуск в Expo Go.

## Структура

```text
src/app/          только маршруты-адаптеры Expo Router
src/pages/        auth, home, profile, listing, editor, chats, conversation, edit-profile, layout
src/features/     edit-listing, change-listing-status, send-message
src/entities/     user, listing, chat, location: модели, состояние и представления
src/shared/api/   HTTP-клиент, offset/size, ошибки, адрес API, хранение токена
src/shared/ui/    тема, кнопки, поля, списки, скелетоны и общий layout экрана
src/shared/lib/   публичные утилиты URL фотографий и генерации UUID
backend/          FastAPI, модели, миграции и серверные тесты
```

Это компактная структура Feature-Sliced Design без пустых слоёв. Зависимости направлены вниз: `app → pages → features → entities → shared`; разрешено пропускать слои. Каждый слайс экспортирует публичный интерфейс через `index.ts`. Внутри слайса используются относительные импорты. Две точечные связи сущностей явно оформлены через `@x`: статус объявления внутри чата и подпись общежития в карточке вещи. Общий UI не импортирует сущности; карточка объявления находится в `entities/listing/ui` и принимает обработчик открытия от экрана.

Стили вынесены рядом с компонентами: например, `pages/home/ui/home-screen.tsx` и `pages/home/ui/styles.ts`. Карточка объявления использует `entities/listing/ui/styles.ts`, общие компоненты — `shared/ui/styles.ts`. В этих файлах находятся и статические StyleSheet, и функции для динамических значений (выбор формата, входящее/исходящее сообщение, safe-area отступы). CSS не используется: это нативные стили React Native. Компоненты корневого layout и вкладок находятся в `pages/layout/ui` рядом со своими `*.styles.ts`; файлы `_layout.tsx` только подключают их, чтобы Expo Router не считал файлы стилей маршрутами.

Единого MarketProvider/useStore больше нет: SessionProvider хранит вход и профиль, ListingProvider — объявления, ChatProvider — переписку. Корневой layout пересоздаёт приватные кеши при смене ID пользователя. Отправка с повторным UUID, смена статуса с expected_status и сохранение объявления/фото с повтором после сбоя находятся в features. Форма и локальные состояния отдельного экрана остаются в pages. Новые зависимости не добавлялись.

Metro исключает backend из сканирования, включая Python-окружение и локальный кластер PostgreSQL. Старый ключ демо-хранилища не используется и не импортируется в реальные аккаунты.

## Проверка

```powershell
npm.cmd run typecheck
npm.cmd test
npx.cmd expo export --platform android --output-dir dist/android
```

15 тестов проверяют границы FSD, публичные API слайсов, отсутствие inline-стилей в компонентах, коды форматов, ID, поля запросов, фотографии, порядок сообщений, Bearer, ошибки и пагинацию. Чистые модели и HTTP-клиент тестируются напрямую без загрузки React Native. Сценарий `scripts/check-ui.cjs` с Playwright проверяет реальные frontend и backend: регистрацию, два аккаунта, поиск, переписку, фото с повтором после ошибки, статусы, профиль, восстановление входа, выход и недействительный токен. Он создаёт уникальные тестовые аккаунты в подключённой локальной базе. Снимки — `artifacts/integration`.

```powershell
# Указать путь к установленному Playwright и при необходимости CHROME_PATH:
$env:PLAYWRIGHT_MODULE='ПУТЬ_К_PLAYWRIGHT'
node scripts/check-ui.cjs
```

Прогон выполнен в Chrome с мобильным viewport и на живой PostgreSQL; Android/Hermes bundle собран. На физическом телефоне приложение в этой сессии не запускалось. Сервер пользователя пока не развёрнут; локальные API/Metro запущены для проверки.
